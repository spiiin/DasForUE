# Own methods and Blueprint events

```das
[ue_class(module_id="example",Blueprintable)]
class Counter {
    properties=ue_properties(EditAnywhere,BlueprintReadWrite) { var Score:int=0 }

    // Script-only helper: no Blueprint node or UFunction is created.
    def Add(amount:int):int { self.Score+=amount; return self.Score }

    [ue_function(BlueprintCallable)]
    def Increase(amount:int):int { return self.Add(amount) }

    // Provides a default DAS implementation and permits child Blueprint overrides.
    [ue_function(BlueprintEvent)]
    def Evaluate(input:int):int { return self.Score+input }

    [ue_function(BlueprintCallable)]
    def Query(input:int):int { return self.Evaluate(input) }
}
```

Own script-only methods and ordinary reflected methods use direct, same-context
DAS calls. Helpers are not part of authoring IR and are not exported UFunctions.
Calls work from reflected methods, helpers and lifecycle callbacks. Recursive
helper calls, mutable ref arguments and arrays are covered by the PIE fixture.
Reflected signatures retain their existing restrictions. Script-only helpers
currently require instance methods and value/void results; static helpers and
reference return values are refused. Named own-method calls are not implemented.

`BlueprintEvent` is a function-kind specifier on `ue_function`; it is unrelated
to `ue_event`, which subscribes to multicast delegates. Event-only annotations
imply callability; an explicit conflicting BlueprintCallable=false is rejected.

`self.Evaluate(...)` routes through the existing typed authored-object method
transport and Unreal ProcessEvent. A child Blueprint override therefore receives
the call. Without an override, the generated adapter executes the default DAS
body. The default body can be empty for a void function.

In the Blueprint override, **Add Call to Parent Function** invokes the inherited
DAS implementation. Omitting that node replaces it completely; the default body
is not run automatically. The inherited body executes on the same UObject, so its
field changes are visible to the child. Function names and signatures must match
the parent's reflected function. The test uses UE's genuine override-graph API,
not a same-name independent function graph.

Ordinary callable functions are marked Final during every Blueprint compilation.
Explicit events and interface implementations remain overridable. UE can retain
BlueprintEvent on its graph-generated UFunctions; Final is the effective override
restriction. The internal DasFunctionKind metadata is generated by the adapter
and consumed by one editor precompile policy.

The event flag is stored in authoring JSON only when true, preserving old wire
formats. Changing a method's callable/event role changes its declaration and
cannot be accepted as body-only hot reload. Reimport conservatively refuses such
role changes on existing Blueprints until dependent override migration is added;
use a new Blueprint for the changed declaration. Signature/data migrations remain
separate from this work.

This stage covers child **Blueprint** overrides and Blueprint parent calls. It
does not implement authored DAS class inheritance, script Super syntax or arbitrary
C++ BlueprintOverride hooks. BeginPlay/Tick/EndPlay keep the existing native host
ordering. Do not label those separate facilities as completed.

See `dsl_method_dispatch_probe.das` and `Scripts/TestMethodDispatchPIE.ps1`.
