# Политика выбора reflected API и метаданных

Selection.json поддерживает обязательные functions и автоматические class_rules.
Экспорт выполняется только в Editor: packaged runtime использует готовые привязки,
а экспорт там отклоняется, поскольку editor metadata может отсутствовать.
Исходный C++ не парсится; классы должны быть загружены.

```json
{
  "policy": {"allow_deprecated": false, "allow_internal": false},
  "functions": [
    {"class": "/Script/DasRuntime.DasObjectFixture", "function": "AddHealth", "alias": "fixture_AddHealth"}
  ],
  "class_rules": [
    {
      "class": "/Script/Engine.Actor",
      "prefix": "actor_",
      "include": ["GetOwner", "SetOwner", "K2_GetActorLocation"],
      "exclude": ["SetOwner"],
      "include_inherited": false
    }
  ]
}
```

## Правила

- functions по умолчанию обязательны: отсутствие или неподдерживаемая сигнатура
  прерывают экспорт, сохраняя предыдущий выходной файл. `required: false` разрешает
  пропуск с диагностикой; этим режимом нужно пользоваться явно.
- class_rules выбирают имена функций по шаблонам Unreal MatchesWildcard с учётом
  регистра. `include` обязателен и непуст; `exclude` имеет приоритет внутри правила.
  Alias получается как prefix + настоящее reflection-имя функции.
- По умолчанию выбираются только функции, объявленные самим классом.
  `include_inherited: true` добавляет унаследованные. IR сохраняет отдельно
  receiver `class` и владельца объявления `declaring_class`.
- Найденные имена сортируются. Автоматические кандидаты с неподдерживаемыми
  сигнатурами пропускаются с причиной. Правило, не нашедшее ни одной функции,
  считается ошибкой. Проверяется правило целиком, а не каждый include-шаблон.
- По умолчанию исключены DeprecatedFunction и BlueprintInternalUseOnly.
  Соответствующие allow_* разрешают их явно, но не отменяют проверку сигнатуры.
  BlueprintProtected, Latent и CustomThunk требуют отдельных адаптеров и не
  экспортируются этим путём.
- Сохранены ограничения instance BlueprintCallable: static/RPC/delegate и
  неподдерживаемые типы параметров не экспортируются. Список не является полной
  моделью всех семантических метаданных Unreal.
- Неизвестные ключи конфигурации, неверные bool, дубли aliases и незагруженные
  классы правил — ошибки. Генератор дополнительно проверяет допустимость aliases
  и коллизии символов. Текущие префиксы: actor_, fixture_, ue_.

При полностью отфильтрованном непустом выборе экспорт может успешно выдать пустой
API с diagnostics. Для обязательного API используйте functions с required=true.
Нет автоматического поиска классов по всем модулям, загрузки assets или полной
политики публичного API движка. Предки выбранных классов добавляются как прежде.

## Дополнительные данные IR v3

Структура вызовов совместима с предыдущим v3. Добавлены
`selection_policy_version: 1`, эффективный `policy` и `diagnostics`.
Каждая диагностика содержит class, function, alias и текст reason.
Причина исключения правилом — excluded_by_rule, устаревшей функции —
deprecated_function, внутренней — internal_function; ошибки сигнатур сохраняют
сообщение общего валидатора marshalling.

У функций сохраняются declaring_class, pure, const и metadata. У классов,
value-структур, их полей и верхнеуровневых параметров также есть metadata.
Фиксированный набор ключей: Category, DisplayName, ToolTip, Units, ClampMin,
ClampMax, UIMin, UIMax, DeprecatedFunction, DeprecationMessage,
BlueprintInternalUseOnly. Отсутствующие ключи не выдумываются.

`parameters[].default_text` берётся из CPP_Default_<имя>, если UHT его сохранил.
Это текст UE, а не выражение daScript. Он не вычисляется и не делает аргумент
необязательным. Clamp/Units тоже пока только описание, без изменения значений.
Enum member metadata и произвольные metadata keys пока не экспортируются.
Текущий генератор использует прежние типы/сигнатуры и игнорирует эти описательные
поля: его исполняемый код для имеющихся 18 функций не изменился.

## Проверка и следующий шаг

Scripts/TestBindingsPolicy.py запускается после сборки редактора. Он проверяет
фильтры, opt-in, наследование, metadata/default_text, повторяемость и сохранность
выходного файла при ошибках. Артефакты: Build/Bindings/PolicyTests.
GenerateBindings.ps1 -Check теперь также обнаруживает изменения metadata и
диагностик, поскольку сравнивает полный IR.

Следующий срез: типизированные значения по умолчанию для поддерживаемых параметров,
с явной обработкой неподдерживаемого текста. Контейнеры, GC-aware объектные поля
структур, AOT и authoring DSL/hot reload остаются последующими задачами.
Синтаксис DSL пользователь выбирает отдельно.


## Результат верификации

Все 9 интеграционных сценариев экспорта прошли, включая точную повторяемость IR,
наследование, policy opt-in и сохранность выходного файла при ошибках конфигурации.
21 тест Python-генератора прошёл; отдельная проверка подтверждает, что изменение
metadata/default_text не меняет исполняемый код. GenerateBindings.ps1 -Check и
прежний тест неподдерживаемой обязательной сигнатуры прошли.
172 foundation-проверки прошли в Editor и 172 — в packaged Win64 Development;
оба процесса завершились с кодом 0. git diff --check прошёл.
Журналы: logs/policy-*.log, Build/Bindings/PolicyTests/*.engine.log.
PIE повторно не запускался: сгенерированные обёртки побайтно совпадают с предыдущим
этапом; текущие изменения проверены экспортом, Editor и packaged запуском.


Обновление следующего этапа: default_text теперь используется для типизированных
optional аргументов поддерживаемых типов. См. Defaults.md; остальные описательные
metadata не влияют на исполнение. Утверждение выше об игнорировании default_text
относится к завершённому этапу политики до реализации defaults.
