# UE vector helpers

`require ue_vector_math` exposes double-precision helpers for Unreal vectors.

- `UE_VECTOR_ZERO`, `UE_VECTOR_ONE` and `UE_VECTOR_FORWARD`, `BACKWARD`, `RIGHT`,
  `LEFT`, `UP`, `DOWN` (each direction uses the `UE_VECTOR_` prefix).
- `UE_VECTOR2D_ZERO`, `ONE`, `RIGHT`, `LEFT`, `UP`, `DOWN` (the `UE_VECTOR2D_` prefix).
- `UE_ROTATOR_ZERO` for zero rotation.
- `dot`, `length`, `length_sq` delegate to the existing native math functions;
  existing native arithmetic operators remain in use.
- `ue_direction_rotation(direction)` produces a pitch/yaw rotator with zero roll.

All 2- and 3-component selections are readable: 36 for UEVector over `xyz` and
12 for UEVector2D over `xy`, including repetitions. Two-component results are
UEVector2D; three-component results are UEVector. There is no float narrowing.
Four-component selections are outside these vector types.

Selections without repeated destinations support `=` and `:=`. The RHS is
snapshotted first, so `value.zyx = value` swaps correctly. Repeated destinations
such as `value.xx = other` are rejected. For a reflected/native property, a clear
read-modify-write form is:

```das
var location = self.Mesh.RelativeLocation
location.xy = anotherLocation.yx
self.Mesh.RelativeLocation = location
```

Readonly globals initialized with literal math constructors, and readonly aliases
of those globals, can be used in `ue_defaults` and authored math property defaults.
The importer expands their literal syntax; it does not call a helper function to
resolve a constant. Mutable globals and function-produced globals are rejected.

The swizzle definitions are generated by `Scripts/GenerateVectorMath.py`. Run the
script to reproduce `ue_vector_math.das`, then use the standard daScript formatter.
