# Управляемые подписки на события Unreal

Репозиторий: `<repo>`.

Первый вариант поддерживает `BlueprintAssignable` dynamic multicast delegates
с одним аргументом `int32`, без возвращаемого значения, `out` или ссылочных аргументов.
Источник выбирается как `self` или `peer` (поле `ADasProbeActor::Peer`).
Подписки объявляются в необязательной экспортированной функции `bind_events()`.
Это временный API runtime, а не выбранный синтаксис DSL.

## Пример

```das
options gen2
require ue_foundation

[export]
def bind_events() {
    ue_subscribe_int("peer", "OnDasSignal", "on_signal")
}

[export]
def on_signal(value:int) {
    ue_state_set_int("total", ue_state_get_int("total", 0) + value)
}

[export]
def main(input:int):int {
    return ue_state_get_int("total", 0)
}
```

Готовый файл:
`Plugins\DasForUE\Content\Das\Scripts\delegate_actor.das`.

Для пробы разместите два `ADasProbeActor`: источник и слушателя. У слушателя
укажите `Peer` на источник и `LifecycleScript = delegate_actor.das` до начала PIE.
Вызовите у источника Blueprint-функцию `EmitDasSignal(5)` или C++
`Source->EmitDasSignal(5)`. У слушателя `ExecuteDas("delegate_actor.das", 0)`
вернёт накопленное значение. Один источник может иметь несколько независимых слушателей.

У `ADasProbeActor` добавлено отражаемое событие `OnDasSignal`. Механизм привязки
проверяет delegate property через UE reflection; имя события не зашито в bridge.
Другие события подходящей сигнатуры у выбранного источника тоже допустимы.

## Reload и владение

`bind_events()` выполняется для каждого кандидата, включая первую версию, до
BeginPlay и до принятия кода. В этот момент подписки только собираются и проверяются:
источник, UE-сигнатура, наличие экспортированного обработчика `void(int)` и дубликаты.
Запись self-свойств и отправка событий через наши API внутри `bind_events()` запрещены.
Именованное состояние копируется в кандидат; изменения кандидата не затрагивают
рабочий контекст до принятия.

После успешной проверки старые подписки снимаются, их идентификаторы отзываются,
контекст заменяется, затем устанавливаются новые подписки. При ошибке остаются
прежние код, состояние и обработчики. Изменение источника или удаление объявления
в новой версии также заменяет набор подписок. Чужие UE-подписки не удаляются.

Начало игры не повторяется: `bind_events()` служит для перепривязки каждой версии,
а `begin_play()` остаётся однократным lifecycle-событием.

Bridge использует отражаемый UObject-прокси и числовой идентификатор подписки.
В delegate не сохраняется указатель на VM-контекст или функцию daScript.
Источник и владелец отслеживаются слабыми ссылками; сам прокси удерживается runtime
до снятия подписки. Обычное поле `Peer` при этом остаётся обычной UE-ссылкой Actor.

При EndPlay подписки снимаются до скриптового обработчика завершения. Destroy,
ReleaseObject, очистка мира, GC владельца и shutdown также освобождают их.
После GC умершего источника его недействительные привязки удаляются.

## Вложенные события

Доставка выполняется на game thread. При внешнем Broadcast обработчик запускается
сразу; если в этот момент уже выполняется скрипт, событие помещается в FIFO-очередь
и доставляется после выхода из VM. Старые идентификаторы после reload или удаления
владельца игнорируются. Очередь ограничена 1024 событиями за один цикл доставки;
сверхлимитные рекурсивные события отбрасываются.

`ue_emit_signal(value)` отправляет `OnDasSignal` текущего ADasProbeActor. Вложенная
отправка из обработчика не вызывает повторный вход в тот же VM-контекст.

Если чужой UE-обработчик уничтожает Actor прямо во время выполнения его скрипта,
привязки отзываются немедленно, а освобождение контекста откладывается до выхода
из VM. Так продолжение текущего вызова не обращается к освобождённой памяти.
Повторный lifecycle-вход в VM пока не поддерживается: при таком вложенном Destroy
скриптовый EndPlay не вызывается повторным входом. Обычный Destroy/EndPIE вне VM
сохраняет проверенную доставку EndPlay. Это ограничение нужно учитывать для
обработчиков, синхронно уничтожающих своего вызывающего Actor.

## Ограничения и следующий шаг

Пока нет произвольных UObject handles вместо self/peer, других сигнатур, single-cast
delegates, worker-thread доставки, скриптовых лямбд и отдельной команды динамической
отписки. Набор подписок меняется декларативно через reload или освобождается вместе
с сессией. Файлы проверяются при обычном вызове скрипта или Tick; Broadcast сам
по себе не запускает компиляцию.

Перенос сессий при structural Blueprint reinstancing остаётся отдельной задачей;
для изменения схемы класса следует остановить PIE. Следующее расширение —
типизированные UObject handles и UFunction-вызовы, чтобы выбирать произвольные
источники событий и работать с более широким API Unreal.


Дополнение: UObjectHandle и `ue_subscribe_object_int` теперь позволяют выбирать
произвольный доступный объектный источник вместо self/peer. См. Docs/Objects.md.
Ограничения сигнатуры самого события (dynamic multicast int32) сохраняются.

Current extension: authored single delegates and multicast Event Dispatchers are described in [DSLAuthoredDelegates.md](DSLAuthoredDelegates.md); the limitations above describe the earlier subscription adapter.
