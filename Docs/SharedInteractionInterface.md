# Общий Interactable в игровом примере

Экспортёр примера использует один интерфейс:
`/Game/DasExamples/Shared/Interactable.Interactable_C`.
Его декларация — `ue_interaction_contract.das`, stable ID —
`dasplayableinteraction.Interactable`.

Раньше каждый запуск CreatePlayableCharacter создавал Interactable внутри новой
папки карты. Копии имели одинаковый stable ID, поэтому глобальный поиск короткого
имени становился неоднозначным. Повторные экспорты в основной smoke-проект
переставали компилироваться.

Теперь FDasInterfaceService::Apply получает постоянную папку Shared. Первый запуск
создаёт интерфейс, последующие используют существующий Blueprint. Экспортёр
сохраняет его отдельно от генерируемой сцены. Pickup реализует именно этот класс,
а ue_interact вызывает тот же класс по явному пути; выбор не зависит от порядка
загрузки других копий. Глобальная проверка неоднозначности остальных типов сохранена.

Старые интерфейсы, карты и Blueprint остаются на месте. Они не мигрируются и
не удаляются; новый экспорт не создаёт дополнительных копий Interactable в папках
Playable/<id>. Для новых карт общий интерфейс является общей зависимостью и должен
попадать в поставку вместе с ними. Packaged-проверка этого изменения пока не запускалась.

## Точечная проверка в основном проекте

```powershell
.\Scripts\TestSharedInteraction.ps1 -SkipBuild
```

Без SkipBuild сначала собирается Editor. Runner запускает 12 async-pickup
сценариев в основном DasForUESmoke, затем ещё раз экспортирует сцену и проверяет
взаимодействие через Enhanced Input -> trace -> интерфейс -> pickup/score/HUD.
Также проверяет наличие общего ассета, отсутствие новых per-map копий и сохранность
SHA256 всех прежних Interactable.uasset в папках Playable.

Отчёт: logs/shared-interface-validation.json. Полные Foundation/PIE/packaged
наборы не входят в эту проверку.
