# Автоматическое обнаружение native-классов

Классы для генерации теперь берутся из `[ue_native_object(path="...")]` в DAS.
Список `DasNativeGameplayClasses()` удалён. Для каждого обнаруженного класса
экспортируется весь поддерживаемый API, включая унаследованные поля и методы.
Анализа того, какие методы вызываются, нет.

## Добавление нового типа

Объявить обёртку в независимом модуле, например `game_native_types.das`:

```das
options gen2
module game_native_types public
require ue_object_types public

[ue_native_object(path="/Script/Engine.PointLightComponent")]
struct PointLightRef { handle:UObjectHandle }

def PointLightRef_from(value:UObjectHandle):PointLightRef {
    return PointLightRef(handle=ue_cast_nullable_object(value,"/Script/Engine.PointLightComponent"))
}
```

В игровом файле импортировать этот модуль и `ue_native_gameplay`:

```das
require game_native_types
require ue_native_gameplay

def set_brightness(light:PointLightRef):void {
    light.SetIntensity(1500.0f)
}
```

Добавлять класс, include или `StaticClass()` в C++ не нужно. Важно, чтобы игровой
файл входил в выбранные исходники генерации либо импортировался из них.

```powershell
# Текущие примеры и их импорты:
.\Scripts\GenerateNativeGameplay.ps1

# Дополнительная входная точка и каталог модулей:
.\Scripts\GenerateNativeGameplay.ps1 -Entry my_game -ScriptDirectory C:\mygame\Das

# Только проверить воспроизводимость уже сохранённых артефактов:
.\Scripts\GenerateNativeGameplay.ps1 -Check -SkipBuild
```

Команда без `-SkipBuild` собирает экспортёр, обнаруживает типы, экспортирует
reflection, генерирует файлы и собирает обновлённый C++ реестр. Генерация запускается
явной командой; она не вызывается автоматически при каждом сохранении DAS-файла.
`-SkipBuild` пропускает обе сборки; при изменении реестра последующая сборка нужна
до использования новых членов.

## Входные исходники и зависимости

`Bindings/NativeGameplay.sources.json` задаёт входные модули, каталоги поиска и
внешние модули. По умолчанию это Character, pickup и ABI fixture. Можно задать
другую конфигурацию через `-Sources`. Это конфигурация исходников проекта,
а не перечень native-классов. Новый импортированный модуль обнаруживается без
изменения конфигурации. Модули сопоставляются с файлами `<module>.das`.

Предварительный лексический проход не требует успешного вывода типов DAS:
будущие сгенерированные методы ещё могут отсутствовать. Он читает `require` и
литеральные native-аннотации, пропуская комментарии и строковые значения.
Пропущенные импорты, неоднозначные файлы, повторные пути типов и неверные пути
вызывают ошибку. Внешние модули без `.das` объявляются явно в конфигурации.

`ue_native_gameplay.das` — результат генерации и не источник новых receiver-классов.
При обнаружении его импорт заменяется обходом рукописного
`ue_native_gameplay_sources.das`. Поэтому сгенерированные dependency views не
расширяют набор классов при каждом повторном запуске. Модуль с каноническими
обёртками должен компилироваться без `ue_native_gameplay`; цикл отклоняется с
диагностикой. Методы, вызывающие сгенерированный API, размещаются в игровом модуле.

Типы параметров и возвращаемых значений по-прежнему получают dependency views;
полный API для них экспортируется, когда их собственные объявления входят в
обнаруженные исходники. Это не бесконечный обход всех классов движка.

## Reflection и ограничения

Предварительный проход создаёт запрос с native-путями и каноническими DAS-именами.
Commandlet загружает соответствующие Unreal-модули и проверяет каждый UClass.
Неизвестный модуль/класс, Blueprint-класс, интерфейс вместо UObject-класса и дубли
не создают частичный выходной manifest. Плагины должны быть включены в проект,
а их модули доступны экспортёру и целевой игре; генерация не меняет Build.cs
или настройки плагинов.

Фильтры поддерживаемых сигнатур сохранены. Произвольные C++ методы без reflection,
latent/custom thunk и прочие неподдерживаемые формы не становятся доступными
автоматически. Причины отказа остаются в `skipped`.

Информация обнаружения записана в build-time `Bindings/NativeGameplay.json`;
runtime использует скомпилированный registry, а не читает JSON.

## Точечная проверка

```powershell
.\Scripts\TestNativeGameplayDiscovery.ps1 -SkipBuild
```

Проверяются лексический проход и импорты, генератор, воспроизводимость,
экспорт нового PointLightComponent из временного DAS-модуля без C++ регистрации,
ошибочные запросы, настоящие вызовы методов автоматически найденного CapsuleComponent
и семь сценариев pickup в отдельном game-процессе. Полные Foundation/PIE/packaged
прогоны не входят в этот runner. Результаты: `logs/native-discovery-validation.json`.

Проверено 2026-10-18: две сборки Editor успешны, 17 проверок обнаружения и
34 проверки генератора прошли. Новый DAS-only PointLightComponent получил 76 полей
и 98 методов; runtime-проверка CapsuleComponent и все 7 сценариев pickup — PASS.
Foundation, полный PIE и packaged build не запускались. Коммит не создавался.
